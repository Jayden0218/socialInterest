## T055 — the visibility matrix, zero skipped rows

```
001/SC-009 + 004/SC-005: 504/504 post assertions run (12/12 post surfaces built).

```

**480 → 522.** The Following feed is surface 13 (twelfth POST surface): 12 × 7 × 6 = 504,
plus 18 review assertions.

The pinned totals in `matrix.spec.ts` had to be raised by hand, which is the design working:
a surface added without touching them fails the suite. And the count only counts because
`surface-routing.spec.ts` refused to pass until the Following feed had a probe proving it
**consults** the boundary — 004 recorded that 462 assertions all running the same `decide()`
would mean one function tested 66 times.

## T056 — SC-017, measured in two places because no harness measures both

`apps/e2e/browser/safety-fit.spec.ts`, 9/9. Two new rows: the **Following tab** and the
**notifications surface**, each asserted reachable at 130% text on a 360×640 viewport, with
both horizontal edges checked as well as the fold — a control pushed off the right edge is as
unreachable as one pushed off the bottom, and only one of the two is ever looked for.

**A browser result does not close SC-017 and is not reported as if it did.** `zoom` is the
browser's stand-in for the platform font setting; react-native-web ignores the real one
entirely, which is exactly why `Avatar`'s overflowing initial could never have been caught
here. The font half is the device run's to answer.
