## The environment changed under this feature, and it matters

Object storage is reachable in this sandbox now — **`adobe/s3mock`, which is not
MinIO**. So `apps/e2e` ran here for the first time, `seed:demo` works, and the
photographs in these captures are real bytes fetched through presigned urls.

**Principle V is not a formality here.** S3Mock verifies no signatures and has
no bucket policy, so **`N-04` cannot pass against it and does not** — that test
asserts an unsigned fetch is REFUSED. It is the environment, not the product,
and N-04 remains verifiable only against MinIO in CI. Reported unverified.

## T051 / T015 — captured, compared, and two drifts fixed

21 screens in `docs/screens/`, captured against a populated store. Two
differences were fixed rather than recorded:

1. **EVERY PUSHED SCREEN WAS HEADED WITH ITS ROUTE NAME.** The interest space
   said `interest`, edit profile said `edit-profile`, post detail said `post`.
   `headerTitle` returned `route.name` under a comment claiming "every base
   route's name reads as its own title" — and it was in every screenshot this
   project has ever taken. Nineteen titles are written out now; a rule that
   title-cased and stripped hyphens would give "Edit Post" and "Open
   Conversation", which are still not what anybody would write.
2. **The interest space's name was not in the interest's colour.** The artboard
   colours the NAME; the screen coloured a rule beside it and left the heading
   plain — two ideas for one thing, where every other surface uses the coloured
   word.

Recorded and NOT fixed: the captures are of a shared local store, so several
interests are named `Fixture caa60384` and the photographs are ffmpeg test
patterns. That is the fixture, not the product.

## T035 — walked as a person, and it finishes

`apps/e2e/scripts/walk-as-a-person.ts`, kept rather than run once and deleted.
It presses what a person presses, in order, and REPORTS instead of asserting —
a suite stops at the first failure and tells you about one thing; this gives you
the list. Five journeys, **every step ok, no page errors**: read the feed and
open a post; comment; open the actions sheet; explore and open an interest;
follow it; find a person and reach mute and block; all four other tabs; compose.

**Its first run was mostly STUCK and almost none of it was the product.** The
store had been reset by an e2e run, so the feed was legitimately empty, and four
ids were ones I had guessed rather than read — `open-comments` for
`comments-button`, `follow-interest-toggle` for `follow-interest-control`.
Confusing a walk's own mistakes for the product's is how run 36 happened.

## Decisions taken, on evidence

- **T044: a new account gets NOTHING, and the empty feed stops offering what is
  not there.** Not content — borrowing `seed:demo` answers a product question
  with a script. "Explore interests" opened a second empty room on a fresh
  install, failing FR-020 and FR-021 on exactly the install they are about. It
  offers "Share your first photo" when the catalogue is empty.
- **T034: "Report account" is on the artboard and is not built.**
  `ReportSubjectType` has no `person`, and adding one files a report an operator
  cannot act on — a person's status is `active | deleting | deleted`, there is no
  suspension, and no moderation action takes a person. Safety is the worst place
  to add an eighth declared-half. **A real gap, needing an operator action
  first.**
- **"Busiest interests", not the artboard's "Busy this week".** The server
  orders by total post count and has no seven-day window. 008/T224 is the
  precedent for not shipping a sentence the product cannot back.

## Defects found by doing this work

- **`postCount` had no writer** and the counts were served from a cache nothing
  refreshed — so `followerCount` had been stale since it was written and
  `suggested()` was sorting by it.
- **`POST /v1/posts` returned the persistence row** (seventh instance).
- **An update that moved a row between indexes did not move it**, costing two
  conversation journeys.
- **013 left `apps/e2e` unrunnable** — 46 failures, a red CI build nobody could
  see from here.
- **Live copy telling people to "create a sub-interest"**, found by 013's
  quickstart §7.
- **`Avatar` crashed Edit profile** on a fixture with no `userId`, which no test
  had reached because none rendered that screen through the shell.
