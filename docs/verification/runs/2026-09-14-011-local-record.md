## Guards watched RED before being trusted

Full output in `011-guard-red-log.md`. Summarised because the count is the point:
**seven** deliberate breaks, and **one of them passed**, which is the finding.

| Break | Caught? |
|---|---|
| Handle claim condition removed | yes — 8 of 8 claims succeed |
| Credential uniqueness condition removed | yes — 5 accounts for one address |
| Constant-time comparison replaced | **NO, first version passed** — see below |
| Naive sign-in (early return) | yes — 45.7x separation |
| `resume()` reverted to `isSignedIn` | yes — rejected-credential test only |
| `console.log` of a submitted password | yes |
| Derived password named in a projection | yes |

**The one that passed is the most useful result here.** The constant-time guard
asserted the FILE contained `timingSafeEqual` and that no `===` appeared in three
hand-guessed spellings. Swapping the comparison for
`derived.toString('base64') === hash.toString('base64')` left the import at the
top of the file untouched — so the file still contained it, none of the guesses
matched, and six assertions reported green over a short-circuiting comparison.

A hand-picked list of ways to be wrong covers only the ways somebody has already
been wrong. It reads the `verifyPassword` body now and asks two questions with no
list in them.

## What is NOT verified, stated plainly

- **Nothing in 011 has run on a device or in a browser.** `35-sign-up-and-out.yaml`,
  the five rewritten sign-in flows, `mint-device-token.ts`'s credential path and the
  updated `apps/e2e` browser specs are **written and unexercised**.
  `verify-maestro-ids` proves every selector resolves against the source, which is a
  claim about names and not about behaviour — and this project has recorded a flow
  whose selector resolved happily and **could not have passed on Android** (`31-mention`,
  a nested `<Text>` with no node of its own).
- **US4 is not built.** A forgotten password is unrecoverable. FR-022 makes that a
  stated condition rather than a broken control: there is deliberately no "forgot your
  password" link.
- **009's session descriptor still prints a live credential** into a world-readable
  job summary. 011 makes that unnecessary — a person can now create an account against
  a session's address — and does not remove it.
- iOS, 002/SC-002 (10,000 concurrent), real usage, and the datastore and hosting
  decisions are unchanged by 011 and all still open.
