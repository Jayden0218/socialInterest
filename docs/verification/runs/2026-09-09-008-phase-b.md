**522 → 564.** Post search is the thirteenth POST surface: 13 × 7 × 6 = 546, plus 18 review
assertions. `surface-routing.spec.ts` reports *"surfaces without a routing probe yet: none"* —
which is the assertion the matrix alone cannot make. Every one of its 546 rows runs the same
`decide()`, so without the routing probe 546 assertions would mean one function tested many
times, and a surface that never consults the boundary would pass every one of them.

US4 adds **no surface**, and that is recorded rather than assumed:
`contracts/visibility-matrix-delta.md` §3a says a sent post is delivered as a message
carrying a postId, so the recipient reads it through the post surfaces that already exist. A
send that widened what a recipient may see would be a second visibility decision, which
Principle II forbids.

## SC-017 — screen size, at 130% text on a 640pt screen

`apps/e2e/browser/safety-fit.spec.ts`, **12/12 green**, with three cases added for Phase B's
controls:

| Case | Control measured | Why this control |
|---|---|---|
| edit profile avatar | `change-avatar` | US5 IS this control. `avatarKey` had no writer before Phase B, so if it falls off the screen there is no other way to set a picture |
| discover posts tab | `search-tab-posts` | A second item in a row, so the risk is horizontal — both edges are checked, which the fold alone would miss |
| post detail share | `share-to-person` | The picker INSIDE the opened sheet, not the button that opens it |

The third is the one that carries the lesson. Run 35's defect was `block-person` at 665px on
a 640px screen **inside a sheet whose entry point was perfectly reachable**, so measuring an
entry point measures the half that was never in doubt. The share sheet is reached through the
viewer's own post via the profile grid rather than through the feed: the ranked feed decides
what a fresh account sees, and a fit measurement that depends on the ranker fails for reasons
that have nothing to do with fit.

**This closes the SCREEN-SIZE half of SC-017 and NOT the font-scaling half.** react-native-web
ignores the platform font setting entirely — which is exactly why 006's `Avatar` overflow was
invisible to every browser journey and every screenshot in `docs/screens` — so `zoom` here is
a stand-in for larger text, not for the platform setting. Only a device run answers the other
half, and until T107 that half is **unverified, not "probably fine"**.

## What Phase B found, and where

- **A THIRD fan-out to the term index.** `updateProcessingState` writes index rows for a post
  becoming ready, and term rows are index rows. Reading the file did not find it;
  `post-search.spec.ts` did, by publishing a post and failing to find it.
- **The FR-022 fallback test failed in the full suite after passing alone**, with `items: 3`.
  It searched a real catalogue interest's NAME, and other journeys publish captions containing
  the catalogue's own words. The table is shared across runs and this is the third
  "regression" in this project that was a grown table. Rewritten to search a **nonce** that
  names both a created sub-interest and a second actor, so both halves of the fallback are
  non-empty by construction and `items: 0` is a fact rather than a hope.
- **And the fix to that had a second version too**: searching as the person carrying the nonce
  reported the people fallback empty, because `PersonSearchService` excludes the viewer from
  their own results. A test failing for its own reason rather than the product's, twice in one
  test — which is the shape this file keeps recording.
- **`Waterfall` reconciled its column children by position.** Keyless children on every render
  of that list, the feed included; found when the post-search surface first rendered through
  it. Keyed through a `Fragment`, because the column's `gap` counts its children and a wrapper
  `View` would have changed the spacing the design specifies.
- **The touch-target guard refused the fallback rows** at `paddingVertical: space.sm`. Sized to
  44 by arithmetic, which is what 007/T078 rewrote that guard to demand.
